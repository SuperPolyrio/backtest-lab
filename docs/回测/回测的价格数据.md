# 别人都用什么样的价格数据
## 1.普通低频框架：OHLCV
Backtrader、Zipline、Backtesting.py、Freqtrade、VectorBT 这类，主输入通常是：
timestamp
open
high
low
close
volume
也就是 K 线 / candle / bar 数据。
Backtrader 官方 CSV feed 就是 datetime/open/high/low/close/volume/openinterest。Zipline 的 bundle 是 pricing data + adjustment data + asset database，实际常用 daily/minute OHLCV。Freqtrade 回测明确加载 candle OHLCV。VectorBT 最常见是直接拿 Close 序列做组合回测。
这类框架适合低频策略、趋势策略、指标策略。它们的问题是：成交价格通常是近似的。如果只用 close 或 next open，就会天然忽略 spread、深度、排队、滑点。

## 2.专业多资产框架：bar + trade tick + quote tick
QuantConnect LEAN、NautilusTrader 这类会更细。它们不只支持 OHLCV，还支持：
TradeBar / Bar
Trade Tick
Quote Tick
QuoteBar
OrderBook / OrderBookDelta
custom data
QuantConnect 区分 trade tick 和 quote tick：trade tick 是真实成交，quote tick 是 bid/ask 报价。QuoteBar 是 bid/ask tick 聚合出来的 bar。
NautilusTrader 更明确，支持：
Bars
Trade Ticks
Quote Ticks
L2 order book deltas
L3 order book / individual orders
custom data

## 3.高频 / 做市框架：L2/L3 order book + trade ticks
HftBacktest 这类框架主打 market replay。它用的是：
L2 Market-By-Price
L3 Market-By-Order
trade tick feed
latency model
queue position model
它的重点不是“价格线长什么样”，而是：
我的订单排在哪里？
盘口有没有足够深度？
后续 trade 有没有打到我的价位？
延迟后还能不能成交？

## 4.预测市场框架：orderbook depth + trades + onchain fills
预测市场更特殊。PolyTest、Telonex、prediction-market-backtesting 这类资料都强调：预测市场不能只用 OHLCV 或 mid price。
它们更看重：
orderbook snapshots
orderbook updates / price_change
best bid / best ask
depth by price level
tick-level trades
onchain fills
market expiry / settlement
PolyTest 的说法很直接：如果假设能按 mid price 买入，回测会明显过度乐观，应该用 orderbook depth 逐档吃单计算平均成交价和滑点。Telonex 也把 prediction market 历史数据拆成 tick-level trades、order books、quotes、onchain fills。
