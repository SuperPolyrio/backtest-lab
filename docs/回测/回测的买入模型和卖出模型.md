所以我的修正判断是：

**Built-in 里面至少应该有两个 execution mode：**

```text
Engine: Built-in

Execution mode:
1. ORDERFILLED_CROSS   默认
2. DEPTH               可选
```

其中：

**ORDERFILLED_CROSS，就是你的价格击穿模型。**  
它适合当前主线，因为你现在最完整、最可信的数据就是 `OrderFilled`。这个模型的含义是：

```text
我在 block N 提交 limit order
之后如果真实 OrderFilled 成交价击穿我的 limit price
并且成交量满足 liquidity cap / participation rate
那我认为我的订单有成交机会
```

这个比直接用 close price、frontend price、mid price 都更对，因为它绑定了真实成交。

**DEPTH，不是替代价格击穿。**  
DEPTH 解决的是另一个问题：

```text
如果我是 taker / FAK / FOK / market order
我当时能不能吃到盘口？
吃几档？
平均成交价是多少？
滑点是多少？
部分成交还是全部成交？
```

这个需要 PMXT L2 / orderbook snapshot。外部资料也是这个方向：Polymarket 官方文档说 market channel 提供 L2 orderbook、price changes、trade executions；订单类型里 GTC/GTD 是挂单，FOK/FAK 是立即吃现有流动性。PolyTest 的回测指南也明确说，真实 fill 要用 orderbook depth 逐档消耗，而不是 mid price。NautilusTrader 的 fill model 讨论里也强调 L2 OrderBook、partial fills、price impact、queue position。

所以真正合理的设计不是“DEPTH vs 价格击穿二选一”，而是：

```text
ORDERFILLED_CROSS:
    默认历史回测模型
    用真实 OrderFilled 证明价格确实被打穿过
    适合 maker limit / 保守历史回测

DEPTH:
    taker / FAK / FOK / market order 模型
    用历史盘口模拟吃单、滑点、部分成交
    适合有 PMXT L2 覆盖的窗口

未来 DEPTH_MAKER_QUEUE:
    用 L2 + 后续 trade flow + queue position
    模拟 maker 排队成交概率
```

我之前说“DEPTH 应该是 Built-in 里的执行模型”，容易让你理解成要把你的价格击穿模型替换掉，这个表达是不对的。准确说应该是：

**Built-in 是你的自研回测框架；价格击穿模型是默认执行模型；DEPTH 是可选的盘口深度执行模型。**

下一步应该改成这样：

```text
前端 Strategy Tester:
Engine: Built-in

Execution mode:
- OrderFilled Cross 默认
- Depth / L2 Taker
```

结果里明确显示：

```text
requested_engine: built_in
actual_engine: built_in
requested_execution_mode: orderfilled_cross
actual_execution_mode: orderfilled_cross

或

requested_execution_mode: depth
actual_execution_mode: depth
book_source: pmxt_l2_sampled
snapshot_id: ...
best_bid / best_ask / levels_consumed / staleness_seconds
```

我的建议很明确：**先把你的价格击穿模型扶正为默认，不要让 DEPTH 抢主线。DEPTH 只在有 PMXT L2 覆盖、并且策略语义是 taker/吃盘口时使用。**
